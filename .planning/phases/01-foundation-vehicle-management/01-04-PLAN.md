## Phase Goal

**As a** vehicle owner, **I want to** add, view, edit, and delete my vehicles (with an optional photo) on both Android and iOS, **so that** I have a trusted offline record of every vehicle I own.

> **Roadmap fidelity note:** the ROADMAP `**Goal:**` line for this phase is outcome-form, not user-story form. The story above is a faithful restatement of ROADMAP success criteria 1–5 and REQUIREMENTS DAT-01…04 / VEH-01…05 — no scope was invented. If the user wants the canonical story committed to ROADMAP.md, run `/gsd-mvp-phase 1`.

<objective>
Complete the Walking Skeleton: replace the placeholder root composable with the real Koin + NavHost + bottom-tab shell, and deliver the thinnest possible end-to-end vehicle slice — type a name, submit, see it in the list, restart the app, still there.

Purpose: this is the MVP-mandated skeleton slice. Every later plan in this phase refines what exists here rather than introducing new architecture: the routes, the tab shell, the ViewModel/`koinViewModel` pattern, the repository boundary and the run commands are all proven working before any polish is added. It also produces `SKELETON.md`, the architectural contract that Phase 2 and Phase 3 build on without renegotiating.

Output: an app where a vehicle added with a name-only form is persisted to SQLite and shown in a shared list, on both platforms, with a documented local full-stack run command.
</objective>
