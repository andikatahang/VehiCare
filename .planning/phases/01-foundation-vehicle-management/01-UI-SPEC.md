# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Stack:** Kotlin Multiplatform + Compose Multiplatform 1.12.1, **Material 3** only.
> shadcn / Tailwind / Radix are **not applicable** — the shadcn initialization gate was skipped by design (project is KMP, not React/Next/Vite). No component registry is used.
> **Scope of this document:** the visual and interaction contract for the shared (`commonMain`) UI. Anything declared here is binding for **both** platforms; iOS-only or Android-only styling forks are prohibited by D-17.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — Compose Multiplatform Material 3 (bundled, `org.jetbrains.compose.material3:material3:1.12.0-alpha03`, based on Jetpack Material3 1.3.2) |
| Preset | not applicable (no shadcn preset) |

| Icon library | **Split, by necessity** — see "Icon Contract" below. Core icons: `org.jetbrains.compose.material:material-icons-core:1.7.3` (pinned — no 1.8.x is published). Vehicle-type icons: 3 bundled vector drawables via Compose Resources. **No new third-party library is added.** |

### Icon Contract (locked — one trap, one decision)

**Verified fact:** `org.jetbrains.compose.material:material-icons-core` and `:material-icons-extended` are **frozen at 1.7.3** on Maven Central (verified against `maven-metadata.xml`, 2026-10-18 — the newest published version is 1.7.3). `material3:1.12.0-alpha03` does **not** declare them transitively (verified against the Gradle module metadata).

**Consequences, both binding:**

1. Core icons **must be declared explicitly** — `Icons.Filled.*` does not compile without them:
   `implementation("org.jetbrains.compose.material:material-icons-core:1.7.3")` (pin `1.7.3`; do **not** use the `compose.materialIconsCore` / `compose.materialIconsExtended` Gradle aliases, which resolve against the CMP version and will not resolve at 1.8.2). `material-icons-extended` is **not** used (deprecated, ~10 MB, and not needed).
2. `DirectionsCar`, `TwoWheeler` and `LocalShipping` **do not exist in the core set**. The three vehicle-type icons required by D-14 are therefore shipped as **Compose Resources vector drawables**, loaded with `vectorResource(...)` — verified cross-platform (Android vector XML in `commonMain/composeResources/drawable/`, works on iOS and Android).

| Icon | Source | Used for |
|------|--------|----------|
| `Res.drawable.ic_vehicle_car` | bundled vector XML | type circle when type = Car · Vehicles tab icon · empty-state visual |
| `Res.drawable.ic_vehicle_motorcycle` | bundled vector XML | type circle when type = Motorcycle |
| `Res.drawable.ic_vehicle_truck` | bundled vector XML | type circle when type = Truck |
| `Icons.Filled.Add` | material-icons-core | FAB · photo-placeholder glyph |
| `Icons.AutoMirrored.Filled.ArrowBack` | material-icons-core | top app bar back arrow (never the deprecated `Icons.Filled.ArrowBack`) |
| `Icons.Filled.Delete` | material-icons-core | leading icon on the destructive "Delete vehicle" button |
| `Icons.Filled.Settings` | material-icons-core | Settings tab icon |

Drawables: 24dp artboard, `fillColor="#FF1C1C1E"` (Ink) so tinting is unnecessary; render at 24dp inside the circle and inside tab items.

## Platform & Theme Constraints (binding)

| Constraint | Rule | Why |
|------------|------|-----|
| Theme | **Light only** in Phase 1. `MaterialTheme(colorScheme = VehiCareLightColors)` is applied unconditionally; `isSystemInDarkTheme()` is **not** consulted. Dark mode is deferred to a later phase. | D-21 defines the interim language as near-black ink on white; a half-tested dark palette would violate the contract it is meant to serve |
| Dynamic color | **Disabled.** Do not use `dynamicLightColorScheme()` / Material You on Android 12+. | Would replace the neutral ink palette with the user's wallpaper palette, breaking D-21 |
| Emphasis | `LocalIndication` / ripple left at Material defaults. No custom indication. | Keeps interaction feedback identical on both platforms (D-17) |
| Text scaling | All type declared in `sp`. **Known limitation:** CMP 1.12.1 does not wire iOS Dynamic Type (that landed later); Android `fontScale` works, iOS system text-size does not. Accepted for Phase 1, recorded in Accessibility. | Prevents re-planning the same gap |

**Required theme mapping (`ui/theme/Color.kt` + `Theme.kt`) — implement exactly:**

```kotlin
val Paper    = Color(0xFFFFFFFF) // dominant surface
val Mist     = Color(0xFFF4F4F5) // secondary surface
val Ink      = Color(0xFF1C1C1E) // accent fill + all primary text/icons
val Slate    = Color(0xFF5C5C61) // secondary text + inactive icons
val Hairline = Color(0xFFE4E4E7) // outlines / dividers
val Danger   = Color(0xFFB3261E) // destructive only

val VehiCareLightColors = lightColorScheme(
    primary = Ink, onPrimary = Paper,
    secondary = Ink, onSecondary = Paper,
    background = Paper, onBackground = Ink,
    surface = Paper, onSurface = Ink,
    surfaceVariant = Mist, onSurfaceVariant = Slate,
    outline = Hairline, error = Danger, onError = Paper,
)
```

## Spacing Scale

Declared values (multiples of 4 — this is the complete set; no other spacing value may be introduced):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gap; label-to-value gap inside a card; inner padding of the license-plate chip |
| sm | 8px | Gap between card title and its meta line; gap between stacked field rows; FAB inset from the bottom edge |
| md | 16px | Default element spacing: screen horizontal padding, card inner padding, vertical gap between list cards, gap between form fields, FAB inset from the right edge |
| lg | 24px | Section padding: space between form field groups, gap between the photo block and the first field, empty-state block padding |
| xl | 32px | Layout gaps: type-circle glyph-to-edge inset is not this — used for the gap between the empty-state visual and its heading, and screen top breathing room below the app bar |
| 2xl | 48px | Major section breaks: gap above the "Service history (coming soon)" slot, gap above the destructive "Delete vehicle" button on Detail, minimum touch target |
| 3xl | 64px | Page-level: vehicle thumbnail / type-circle diameter, list bottom content padding (clears the FAB), empty-state top offset |

**Exceptions:** none. Every spacing value in Phase 1 is drawn from the seven tokens above. The only deliberate deviation from Material defaults is called out in Component Dimensions (FAB bottom inset = `sm` 8px, not Material's 16px, so the 56dp FAB sits exactly inside the 64dp (`3xl`) bottom content band and never occludes the last card).

## Typography

**Declared sizes: 4 (14, 16, 20, 24sp). Declared weights: 2 (400 Regular, 500 Medium). Nothing else may appear.** The M3 text-field label's built-in 0.75 scale animation is a component transform, not a fifth size.

| Role | Size | Weight | Line Height | M3 slot | Applied to |
|------|------|--------|-------------|---------|------------|
| Display | 24sp | 500 | 28sp (1.17) | `headlineSmall` (weight override) | **Vehicle name on the Detail screen only** — the single largest text in the app |
| Heading | 20sp | 500 | 24sp (1.2) | `titleLarge` (size override from 22) | Top app bar title · delete-dialog title · empty-state heading |
| Title | 16sp | 500 | 24sp (1.5) | `titleMedium` | Vehicle name on list cards · form section label ("Vehicle type") |
| Body | 16sp | 400 | 24sp (1.5) | `bodyLarge` | Text-field input text · Detail field values · `make · model · year` line · dialog and empty-state body · Snackbar text |
| Label | 14sp | 500 | 20sp (1.43) | `labelLarge` | Buttons · bottom-tab labels (override M3's 12sp `labelMedium`) · license-plate chip · Settings "App version" row · "Service history (coming soon)" hint · Detail field labels |

Notes:
- Body line height is **1.5** (16 × 1.5 = 24sp), Heading line height is **1.2** (20 × 1.2 = 24sp).
- Hierarchy comes from **size + weight + tone** (`Ink` vs `Slate`), never from color. `Slate` is used for all secondary text: the meta line, Detail field labels, the "coming soon" hint, inactive tab icons/labels, and the em-dash placeholder for empty optional values.
- Both platforms use `FontFamily.Default`, so iOS renders SF Pro and Android Roboto; glyph metrics differ slightly. Type sizes are therefore declared as fixed `sp` values via `MaterialTheme.typography` overrides — do not ship a custom font to normalize this.
- Override the M3 slots used above in one `VehiCareTypography` object; do not rely on M3 defaults (they introduce 12sp and 22sp, i.e. sizes outside the declared scale).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | App background, top app bar, bottom navigation surface, text-field container |
| Secondary (30%) | `#F4F4F5` | Vehicle cards, type-icon circle fill, photo placeholder block, plate chip, segmented-button track |
| Accent (10%) | `#1C1C1E` | Reserved list below — **exhaustive** |
| Destructive | `#B3261E` | Destructive actions only (`Delete vehicle`) |
| Support — primary text/icon | `#1C1C1E` | All primary text and icons (this is the same token as the accent; see note) |
| Support — secondary text | `#5C5C61` | Meta lines, field labels, hints, inactive tabs (contrast on white ≈ 6.4:1) |
| Support — outline | `#E4E4E7` | Unfocused text-field borders, dividers |

**Split:** white ≈ 60% of painted area (all backgrounds), `Mist` ≈ 30% (cards/placeholders/chips), accent ≈ 10% (FAB + up to one filled CTA + the selected tab indicator per screen).

**Accent reserved for — exactly these six things, nothing else:**
1. FAB container fill on the vehicle list (glyph renders `Paper` white).
2. The empty-state primary CTA button fill ("Add vehicle"; label renders `Paper` white).
3. The Add/Edit form's primary submit button fill ("Add vehicle" / "Update vehicle").
4. The selected bottom-tab icon tint **and** its M3 indicator pill.
5. The focused outlined-text-field border and its floating label.
6. The required-field marker `*` beside the "Name" label.

**Explicitly NOT accent:** the back arrow (Slate) · unselected tab icons and labels (Slate) · card surfaces and their ripple · card meta text (Slate) · Detail field labels and values · secondary buttons — "Replace photo", "Remove photo", "Cancel", "Try again" (outlined/text style, `Ink` label) · the "Service history (coming soon)" hint (Slate) · any body text.

**D-21 note (accent deferred by the user):** Phase 1 has **no brand accent color**. The accent value equals the ink token so the app reads as near-black on white, exactly as the user requested. The accent is exposed as a single token in `Color.kt`; when the user chooses a real accent after seeing the build, changing that one value re-tints all six reserved surfaces with no layout change. **This revisit is tracked and must not be pre-empted in Phase 1.**

## Visual Hierarchy & Focal Points

**Hierarchy statement:** every screen carries exactly **one** maximum-weight element, and hierarchy is expressed through three levers only — size (24 / 20 / 16 / 14sp), weight (500 for the primary line, 400 for supporting lines), and tone (`Ink` on `Paper` vs `Slate`). No screen uses color to create hierarchy, because Phase 1 has no brand accent (D-21).

| Screen | Focal point (first element the eye must land on) | Second level | Recessive level |
|--------|--------------------------------------------------|--------------|-----------------|
| Vehicle list — **empty** | The empty-state heading ("No vehicles yet") stacked with the prominent "Add vehicle" CTA | Empty-state body copy | The 64dp car visual above the heading |
| Vehicle list — **populated** | The **first (newest) card's vehicle name**; the FAB is the action anchor in the lower-right | Card meta line | Plate chip, then the thumbnails |
| Vehicle detail | The **vehicle name** (24sp `Display`) directly under the hero photo | Hero photo | Field rows, then the "coming soon" hint, then the destructive button |
| Add / Edit vehicle | The **focused "Name" field** (autofocus + keyboard) | Remaining fields in order | The photo block, last |
| Settings | The single "App version" row | — | — |

Deletion is intentionally the **lowest** visual weight on Detail (last element, below a `2xl` 48px break) while still being plain-text-labelled — discoverable, never accidental (D-18).

## Screens & Component Inventory

One `NavHost` in `commonMain`; the bottom tab shell is shared by both platforms (D-17). Routes are the `@Serializable` types from RESEARCH.md Pattern 6 — reuse them, do not invent new ones.

| # | Destination | Scaffold composition | Components used |
|---|-------------|----------------------|-----------------|
| 1 | `VehicleListRoute` (home, Vehicles tab) | `Scaffold` + `TopAppBar("Vehicles")` + `FloatingActionButton` + shared `BottomTabs` | `VehicleCard` × N (or `EmptyState`), `LicensePlateChip`, `VehicleTypeCircle` |
| 2 | `VehicleDetailRoute(id)` | `Scaffold` + `TopAppBar(<name>, back arrow, "Edit" text action)` | `HeroPhoto`, `VehicleTypeCircle`, `FieldRow` × 5, `ComingSoonSlot`, destructive `DeleteVehicleButton`, `ConfirmDeleteDialog`, `Snackbar` host |
| 3 | `VehicleEditRoute(id = 0 \| N)` (Add **and** Edit) | `Scaffold` + `TopAppBar("Add vehicle" \| "Edit vehicle", back arrow)` | `PhotoField`, `OutlinedTextField` × 5, `VehicleTypePicker`, primary `Button`, inline error text |
| 4 | `SettingsRoute` | `Scaffold` + `TopAppBar("Settings")` | `SettingsRow("App version")` — the only content (D-17) |
| 5 | `BottomTabs` (shared) | `NavigationBar` | 2 items: Vehicles (`ic_vehicle_car`) · Settings (`Icons.Filled.Settings`) |

**VehicleCard layout (D-14):** horizontal row, `md` 16px padding, `sm` 8px gap between the leading visual and the text column.
`VehicleTypeCircle` 64dp → text column: name (`Title`, `Ink`) / `make · model · year` (`Body`, `Slate`) / `LicensePlateChip` (`Label`, `Ink` on `Mist`).
- Omit a blank optional segment *and its separator*: `"Toyota Corolla"` when make/truck… e.g. make="Toyota", model="Corolla", year=null → `"Toyota · Corolla"`. If all three are blank, omit the meta line entirely (do not render a lone `·`).
- Omit the plate chip when the plate is blank (D-12 makes it optional).
- Separator is the middle dot `·` (U+00B7) with a single space either side. **Locked.**

**Detail field rows (D-18, agent discretion — locked here):** order is `Make → Model → Year → License plate → Type`. Two-column row: label (`Label`, `Slate`) leading, value (`Body`, `Ink`) trailing, `sm` 8px gap, 1dp `Hairline` divider between rows. A blank optional value renders the em dash `—` in `Slate` (the row is **not** hidden, so the Detail screen has a stable shape as fields get filled). The plate row renders the chip instead of plain text. After the rows: a `2xl` 48px break, then `ComingSoonSlot` ("Service history (coming soon)" in `Label`/`Slate` inside a `Mist`, 12dp-radius, `md`-padded container), then a `2xl` 48px break, then `DeleteVehicleButton`.

**Add/Edit form field order (agent discretion — locked here):** `Name` → `Make` → `Model` → `Year` → `License plate` → `Type` → `Photo`.
Rationale: D-09's "logging a car must be fast" means the **required** field is first and autofocused (keyboard opens immediately, so a fast add is type-name → submit); the optional photo — the heaviest interaction — is last so it can never sit under the keyboard or block a quick add. The form is a single screen (D-08), one `Column` with `lg` 24px between field groups.
- Name: `OutlinedTextField`, `singleLine`, autofocus on Add, label "Name", required marker `*` in accent.
- Make / Model: `OutlinedTextField`, `singleLine`, free text.
- Year: `OutlinedTextField`, `singleLine`, `KeyboardOptions(keyboardType = KeyboardType.Number)`, input filtered to digits only, **max 4 characters**. No range validation — deliberately, per D-13.
- License plate: `OutlinedTextField`, `singleLine`, free text, **no format hint, no uppercase transform** (D-12 locks "no format validation, no format hint").
- Type: `SingleChoiceSegmentedButtonRow` with exactly three segments — Car · Motorcycle · Truck (D-10). **Exactly one is always selected; "Car" is preselected** (matches the schema's `type TEXT NOT NULL DEFAULT 'Car'`). This resolves D-09's "type is optional" without a nullable state. *Fallback if the segmented control misbehaves on iOS in CMP 1.12.1: a row of three `FilterChip`s with the same single-select semantics — the copy, order and default do not change.*
- Photo: `PhotoField` — 16:9 `Mist` block. Empty: centered `Add` glyph + "Add photo" text button. Filled: the image, with "Replace photo" (outlined) and "Remove photo" (text) buttons beneath.

## States & Interaction Contract

Every screen must implement these states explicitly. No state may render a blank white area.

| Screen | State | Required rendering |
|--------|-------|--------------------|
| Vehicle list | Loading | Centered M3 `CircularProgressIndicator` (accent = `Ink`) on `Paper`; no skeleton shimmer, no placeholder cards |
| Vehicle list | Empty | `EmptyState`: 64dp `ic_vehicle_car` in a `Mist` circle (`xl` 32px below), Heading "No vehicles yet", Body copy, then a **filled** "Add vehicle" CTA button. The FAB remains visible (D-19 — the empty state has its own big CTA) |
| Vehicle list | Content | `LazyColumn`, newest first (D-16), `md` 16px horizontal padding, `md` 16px between cards, `3xl` 64px bottom content padding |
| Vehicle list | Error | Centered: Body copy (load error) + an outlined "Try again" button. FAB stays visible; the empty state is **not** shown on error |
| Detail | Loading | Centered progress indicator while the row is fetched by id |
| Detail | Not found (e.g. deleted on another device path) | Body copy stating the vehicle is no longer available + a "Back to vehicles" outlined button |
| Add/Edit | Idle | Normal form |
| Add/Edit | Invalid | Submit stays enabled only when `name` is non-blank after trimming; if the user types then clears the name, supporting error text appears under the Name field (destructive-tinted only for the text, not the field) |
| Add/Edit | Saving | Submit button shows M3 `CircularProgressIndicator` in place of its label; all inputs remain readable but input is disabled |
| Add/Edit | Save failed | Dialog dismissed, form retained, `Snackbar` with the save-error copy and a "Try again" action |
| Any save/delete | Success | No celebratory animation. Add → pop back to the **list** (the list is Flow-driven and shows the new card). Edit → pop back to **Detail** (shows updated values) |

**Interaction rules (binding):**

| Interaction | Contract |
|-------------|----------|
| Tap a card | Navigate to `VehicleDetailRoute(id)`. Ripple from the M3 `Card` default. **There is no long-press gesture on the list — ever** (D-18). |
| Tap FAB | Navigate to `VehicleEditRoute(id = 0L)`. `contentDescription` = "Add vehicle". |
| Back arrow | `Icons.AutoMirrored.Filled.ArrowBack`, pops the back stack. iOS system back-swipe must work in addition (D-20: no gesture-*only* navigation, never gesture-*less*). |
| Detail → Edit | "Edit" **text** button in the top app bar actions (no icon — the simple title bar stays clean, D-20). Navigates to `VehicleEditRoute(id)`. |
| Detail → Delete | Pressing "Delete vehicle" opens `ConfirmDeleteDialog`. Nothing is deleted before confirmation. |
| Confirm dialog | M3 `AlertDialog`: title "Delete vehicle", message "Delete {name} and all its records?", dismiss = "Cancel" (`TextButton`, `Ink` label, **not** destructive-tinted), confirm = "Delete vehicle" (`TextButton`, `Danger` label). Dismissing by back/outside tap = cancel. |
| Delete succeeds | Pop back to the list; `Snackbar` "Vehicle deleted." No undo in Phase 1 (deliberately out of scope). |
| Delete fails | Dialog closes, detail screen stays, `Snackbar` with the delete-error copy. The vehicle is **not** removed from the UI. |
| Photo field | Gallery picker only (D-04) — no camera entry point is rendered anywhere. Cancel returns to the previous state unchanged. Replacing a photo keeps the form's other values untouched. |
| Tab switch | `NavigationBar` selection follows the current destination; tapping Vehicles from Settings returns to the list. Tab selection must stay in sync with the nav back stack in both directions. |

## Accessibility

| Requirement | Contract |
|-------------|----------|
| Touch targets | Every interactive element ≥ **48dp × 48dp** (`2xl`). Text buttons get `Modifier.defaultMinSize(minHeight = 48.dp)`; list cards are ≥ 88dp tall; tab items use the M3 `NavigationBar` default. |
| Content descriptions | Icon-only controls carry one: FAB → "Add vehicle"; back arrow → "Back"; type circle → the type name ("Car"/"Motorcycle"/"Truck"); vehicle photo → "Photo of {name}" with a decorative-null fallback when the name is blank. |
| Card semantics | The card merges its descendants (`Modifier.semantics(mergeDescendants = true)`) so it is announced as one node: name, then the meta line, then "License plate {plate}". |
| Contrast | All text ≥ 4.5:1 on its background: `Ink` on `Paper` ≈ 17:1, `Slate` on `Paper` ≈ 6.4:1, `Danger` on `Paper` ≈ 6:1, `Paper` on `Ink` ≈ 17:1 (FAB / filled CTA). |
| No colour-only meaning | The destructive action is a **worded** button ("Delete vehicle") in addition to its colour; the required field carries a `*` **and** supporting error text; selected state on tabs/segments is not conveyed by colour alone (M3 indicator pill / selected segment outline). |
| Form errors | Supporting error text is announced via the `OutlinedTextField`'s built-in error semantics (`isError = true` + `supportingText`), so screen readers read the message with the field. |
| Text scaling | All type in `sp`; no fixed-height text containers. Android `fontScale` is respected. **Known Phase-1 limitation:** iOS Dynamic Type is not wired by CMP 1.12.1 — record it, do not fork the UI for it (D-17). |
| Motion preference | No animation in Phase 1 is load-bearing (see Motion), so no reduced-motion branch is required. |

## Motion

Deliberately minimal — Phase 1 ships **no custom animation**:

| Where | Motion |
|-------|--------|
| Screen transitions | Navigation Compose 2.9.0 platform defaults (iOS push/pop, Android default). No custom `enterTransition`/`exitTransition`. |
| Press feedback | M3 default ripple. |
| FAB / dialog / snackbar / segmented selection | M3 component defaults only. |
| List updates | **No** enter/exit or reorder animation on the card list. New cards appear immediately (D-16 order is by id desc). |
| Explicitly banned | Skeleton/shimmer loaders, confetti or celebratory animation on save, animated empty-state illustrations, custom hero/parallax transitions. |
