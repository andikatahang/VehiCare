<objective>
Lay the Phase 3 data foundation: ship the `reminder_rule` schema as version 4 (D-62), and make the process-wide `VehiCareDatabase` constructible by non-Compose components without creating a second driver (D-63).

Purpose: every later plan in this phase — the due-state engine, the repository, both screens, the dashboard and the notification worker — depends on these two facts. The SQLDelight listener registry lives on the driver instance, so a second `VehiCareDatabase` would make worker writes invisible to the UI (03-RESEARCH Pattern 1). The holder is what lets the Android `CoroutineWorker` read the same database the UI observes.

Output: `ReminderRule.sq`, `migrations/3.sqm`, the regenerated `4.db` baseline, two new flat baseline queries in `ServiceEntry.sq`, `DatabaseProvider`, the re-wired Koin graph, one construction point per platform, and the `ReminderRule` domain model the next plans build on.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Platform entry point → `DatabaseProvider` | Process startup code decides which single driver the whole app sees. |
| Koin graph → SQLDelight | Every repository resolves the holder; a second construction path would silently split change notification. |
| `.sqm` migration → on-disk data | A migrated schema must equal the `.sq` schema or existing rows become unreadable. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | `DatabaseProvider` / `AppModule` | mitigate | Single holder with `check(holder == null)`; the Koin fallback that could construct a second driver is deleted (C-3); verification greps assert no `createDriverFactory` remains in `commonMain` and exactly one `initialize` per platform. |
| T-03-02 | Tampering | `3.sqm` vs `ReminderRule.sq` | mitigate | DDL written identically in both files; `verifyCommonMainVehiCareDatabaseMigration` plus the regenerated-`4.db` diff guard fail the build on any drift (D-62). |
| T-03-03 | Information disclosure | local `vehicare.db` | accept | Data is local-only vehicle maintenance state (no credentials, no PII beyond a plate); research V6 records no at-rest encryption by design. |
| T-03-04 | Denial of service | startup | mitigate | `initialize` is called before Compose on both platforms; `require()` fails with an explicit message rather than a null dereference; `check` prevents a double init from silently replacing the driver. |
| T-03-SC | Tampering | Gradle dependency resolution | mitigate | This plan adds no dependency and does not touch the version catalog; the phase's only install (`androidx.work:work-runtime:2.12.0`) is gated in plan 07 by the approved Package Legitimacy Audit. |
</threat_model>
