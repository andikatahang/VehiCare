<objective>
Give the phase its persistence, its copy and its notification-identity contract: a `ReminderRepository` over the v4 schema with the atomic once-per-cycle claim (D-51), the D-64 cascade inside the existing vehicle delete, the complete Phase 3 string block (D-65), the single resource-bound sentence resolver (C-28/C-40) and the identifier helper both platforms' taps parse (D-55).

Purpose: this is the plan that turns the pure state machine into something the screens and the worker can actually use, and it is the plan that makes C-28 mechanically true — after it, no surface is allowed to format a due state by hand because there is exactly one function that can. The notification claim belongs here too: it is a single conditional `UPDATE` whose affected-row count is the only safe "notify once" decision (an in-memory set resets on every launch and re-nags).

Output: `ReminderRuleEntityMapper`, `ReminderRepository`/`ReminderRepositoryImpl` (rules, baselines, vehicle stats, claim, cascade hook), the extended `VehicleRepositoryImpl.delete`, one `AppModule` binding, `ReminderCopy`, `ReminderNotificationId`, `RupiahFormat.formatKmValue`, the full Phase 3 string block, and real-driver tests for the claim/baseline/cascade semantics plus `commonTest` suites for the two pure helpers.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Repository write → notification decision | The conditional `UPDATE` is the only atomic claim; a wrong implementation re-notifies on every launch (D-51). |
| `service_entry_type` rows → baseline | The baseline is derived data; using the position-0 mirror or a different row's mileage silently shifts every due date. |
| Vehicle delete → child rows | Foreign keys are never enabled, so an omitted delete leaves orphaned rules that still resolve baselines. |
| Resource strings → notification body | Both platforms post text produced here; divergent formatting would make the notification contradict the card (C-40). |
| Notification identifier → navigation | An unvalidated payload would navigate to a wrong or non-existent vehicle (D-55). |
