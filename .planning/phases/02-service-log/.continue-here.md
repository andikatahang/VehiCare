## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| No-worktree parallelism assumption | If you assume subagents run in parallel, you'll dispatch multiple executors that clobber each other on the main tree. Discovered: OpenCode has no worktree isolation; executor A and B would stage conflicting files. | blocking | Orchestrator serializes all plans on the main tree. Every executor prompt contains the `critical_working_tree_rule`. Never batch spawn. |
| Xcode sniff instead of KMP tasks | The generic post-merge step would pick `iosApp.xcodeproj` and run `xcodebuild test`, which fails for this KMP project. Discovered: 01-04 executor used the sniffed command; orchestrator now runs explicit Gradle tasks. | blocking | Orchestrator overrides the step with explicit task list. Executors must use the same tasks the plan names. |
| `git add -A` / `git commit -a` | Executor staged and committed the user's uncommitted `pbxproj` re-serialization. Discovered: 01-06 executor almost did this; explicit instruction added to every executor prompt. | blocking | Every executor prompt has the `critical_working_tree_rule` listing the exact protected file. Stage only task-named files. |
