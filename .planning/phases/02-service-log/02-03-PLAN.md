## Phase Goal

**As a** vehicle owner, **I want to** log every service event — date, mileage, type, cost, notes, parts, workshop, and photos — and browse, edit, or delete any vehicle's full history, **so that** I have a trustworthy record of all maintenance performed.

> **Roadmap fidelity note:** the ROADMAP `**Goal:**` line for this phase is outcome-form, not user-story form. The story above is a faithful restatement of ROADMAP success criteria 1–5 and REQUIREMENTS SVC-01…SVC-07 — no scope was invented. If the user wants the canonical story committed to ROADMAP.md, run `/gsd-mvp-phase 2`.

<objective>
Build the Add/Edit service entry slice: the form components (type chips, custom-type dialog, date field + picker, parts rows, photo strip), the pure validation object, the edit ViewModel with promise-grade photo bookkeeping, and the single scrolling screen — registered as one destination for add (`entryId == 0L`) and edit (D-08 pattern).

Purpose: this is the phase's headline capability — the 30-second path (D-31) lives or dies here. Everything the user types, taps or picks flows through this slice into the repository built in 02-01, formatted by the utilities built in 02-02.

Slice position (MVP): the storage-and-input half of "log a service event". The destination is registered and complete in this plan; its entry points (history FAB/CTA, detail Edit action) land in 02-04/02-05 — until then nothing navigates to it, so no stopgap UI exists at any commit.

Output: five form components, `PhotoStorage` extended with the directory parameter (vehicle call sites untouched), a tested form-validation object, the edit ViewModel honouring the seven per-path photo rules, and the wired `ServiceEntryEditRoute`.
</objective>
