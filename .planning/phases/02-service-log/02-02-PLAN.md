## Phase Goal

**As a** vehicle owner, **I want to** log every service event — date, mileage, type, cost, notes, parts, workshop, and photos — and browse, edit, or delete any vehicle's full history, **so that** I have a trustworthy record of all maintenance performed.

The story above is a faithful restatement of ROADMAP success criteria 1–5 and REQUIREMENTS SVC-01…SVC-07 — no scope was invented. If the user wants the canonical story committed to ROADMAP.md, run `/gsd-mvp-phase 2`.

<objective>
Add the phase's single new dependency and the two pure utilities every service screen formats or converts through, plus the complete Phase 2 string set in the centralized resource file.

Purpose: the date variable and the two numeric formats are the phase's most cross-cutting display concerns, and the string set is the input every UI plan compiles against. Output: kotlinx-datetime wired through the catalog, `ServiceDates` + `RupiahFormat` implemented with unit tests, and `strings.xml` carrying the full UI-SPEC string contract.
