## Phase Goal

**As a** vehicle owner, **I want to** log every service event — date, mileage, type, cost, notes, parts, workshop, and photos — and browse, edit, or delete any vehicle's full history, **so that** I have a trustworthy record of all maintenance performed.

> **Roadmap fidelity note:** the ROADMAP `**Goal:**` line for this phase is outcome-form, not user-story form. The story above is a faithful restatement of ROADMAP success criteria 1–5 and REQUIREMENTS SVC-01…SVC-07 — no scope was invented. If the user wants the canonical story committed to ROADMAP.md, run `/gsd-mvp-phase 2`.

<objective>
Replace the vehicle Detail's reserved Phase 2 placeholder with the real summary row it was reserved for: the entry count and last service date, tappable, opening the history screen — and retire the placeholder file and its string.

Purpose: this is the phase's last integration point and the one Phase 1 deliberately left open ("when Phase 2 lands it replaces or wraps this slot — nothing outside this file needs to change"). It is also the entry point that makes the history screen reachable, so the phase is only complete once a user can get there from a vehicle.

Slice position (MVP): closes the loop — the Detail screen already showed the vehicle; now it shows the vehicle's service story in one line and one tap away. With this plan, every SVC requirement is reachable through shipped UI: add/edit (02-03), read/delete an entry (02-04), browse (02-05), and discover it all from the vehicle (here).

Output: the aggregate-backed `ServiceSummaryRow`, its small ViewModel, the vehicle Detail wired to it with an injected navigation callback, and the placeholder plus its string deleted.
</objective>
